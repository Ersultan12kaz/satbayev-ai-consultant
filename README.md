# Satbayev AI Consultant — мультиязычный виртуальный ассистент на основе RAG

**Тема дипломной работы:** «Интеллектуальный мультиязычный виртуальный ассистент для студентов университета на основе технологии RAG»
**Авторы:** Ерсултан, Айбол, Алихан — Satbayev University

Ассистент отвечает на любые вопросы студентов Satbayev University (RU / KZ / EN) — учёба, экзамены, стипендии,
общежития, академический отпуск, перевод, практика, военная кафедра, история университета и т.д. — и вежливо
отказывается отвечать на вопросы, не связанные с университетом.

**Порядок источников:** официальные документы (<https://official.satbayev.university/ru/docs>) + сайты
official.satbayev.university и satbayev.university → Википедия (бесплатно, без ключа, только о университете и
К. Сатпаеве) → «не найдено».

**Как отвечает (состояние на 28.09.2026):**
- ответ на языке вопроса: если правило есть только на русском, его переводит **наша модель перевода**
  (Transformer 52 M, обучен с нуля, chrF 56.4);
- «своими словами» — **наша языковая модель** (GPT 42 M, собственный BPE-токенизатор 32 000, обучена с нуля на
  ≈1.2 млрд токенов, затем дообучена на 67 280 примерах «вопрос → документы → ответ»); её ответ принимается только
  после проверок (факты и числа есть в документах, язык вопроса, связь с вопросом, нет «мусора»), иначе
  используется ответ композитора из предложений документов;
- помнит разговор («толығырақ айтшы», «қазақша айтшы»), без ограничения числа вопросов;
- источники скрыты по умолчанию (включаются в настройках портала).

> Все модели обучаются нами с нуля. Внешние готовые/платные модели и API (ChatGPT и т.п.) **не используются**.

**Қазақша қысқаша:** ассистент студентке қатысты кез келген сұраққа сұрақ тілінде (қаз/орыс/ағыл) жауап береді:
алдымен құжаттар мен университет сайттарынан, табылмаса Википедиядан іздейді, артық сұрақтарға жауап бермейді.
Барлық модель (іздеу, классификаторлар, LLM, аудармашы) өзіміз нөлден оқыттық. Қорытынды тест: `reports/final_test_report.md`.

## Архитектура

```
Student ──► Web frontend (HTML/CSS/JS, RU/KZ/EN) ──REST──► FastAPI backend
                                                            │
             ┌──────────────────────────────┬───────────────┼──────────────────┐
             ▼                              ▼               ▼                  ▼
   Language detection (наша NB)   Scope classifier    RAG engine          PostgreSQL / SQLite
                                  (наша LogReg)          │                users, conversations,
                                                         ▼                messages (логи), documents,
                                  Query embedding (наша модель)          document_chunks (+ pgvector)
                                                         ▼
                                  Dense / BM25 / Hybrid search (Top-K)
                                                         ▼
                                  Reranker (наша learning-to-rank модель)
                                                         ▼
                                  Hallucination guard (порог «не найдено»)
                                                         ▼
                                  Grounded generator ──► Answer + Sources + Confidence
```

## Модули и что именно обучается

| # | Модуль | Алгоритм | Данные для обучения |
|---|---|---|---|
| 1 | Сбор документов | краулер разделов «Внутренние нормативные документы» (RU/KZ/EN) | official.satbayev.university |
| 2 | Обработка | PDF/DOCX/DOC/XLS → текст (старые .doc/.xls читает собственный парсер OLE2/Word/BIFF8 — `ml/msdoc.py`; PDF со сломанной кодировкой казахского шрифта распознаются OCR) → удаление колонтитулов/номеров страниц/переносов → chunking (~160 слов, overlap 35) с метаданными (документ, страница, раздел, язык) | — |
| 3 | **Language detection** | мультиномиальный Naive Bayes на символьных n-граммах (1–3), реализован с нуля | предложения документов, метка = язык раздела сайта (с очисткой шумных меток) |
| 4 | **Scope classifier** | TF-IDF (слова + char n-grams) → логистическая регрессия, оптимизатор Adam (наша реализация) | шаблонные вопросы по 40+ темам университета + вопросы из заголовков документов vs off-topic |
| 5 | **Embedding-модель** | этап 1: sub-word TF-IDF → SVD (LSA); этап 2: контрастивное дообучение проекции W функцией InfoNCE (in-batch negatives), градиенты выведены вручную (проверяются тестом) | пары (вопрос, фрагмент) из Inverse Cloze Task + заголовки разделов |
| 6 | Поиск | Dense (cosine), BM25, Hybrid = 0.7·dense + 0.3·BM25 (min-max нормализация) | — |
| 7 | **Reranker** | learning-to-rank (логистическая регрессия) на 13 признаках: dense, BM25, ранги, лексическое пересечение, биграммы, совпадение с заголовком, язык… | Top-20 кандидатов для автосгенерированных вопросов + off-topic |
| 8 | Защита от галлюцинаций | порог по вероятности reranker'а (подбирается по F0.5) → «информация не найдена»; scope-классификатор → «я отвечаю только по вопросам университета» | — |
| 9 | **Тип вопроса** | softmax-регрессия (TF-IDF слов + char n-grams), 8 классов | шаблонные вопросы × темы университета на 3 языках (+ написание без казахских букв) |
| 10 | **Ранкер предложений + композер ответа** | логистическая регрессия на 11 признаках (пересечение с синонимами, dense, тип вопроса ↔ «сигнальные» слова, числа, язык…); ответ «Коротко + шаги/список» с цитатами [n] | self-supervised: псевдо-вопрос из предложения документа, кандидаты — предложения того же и найденных фрагментов |

### Понимание вопросов «своими словами»

Студенты пишут не языком документов: «обшагаға қандай документтер керек», «академка калай алам», «как получить общагу».
Для этого добавлено:

| Компонент | Что делает |
|---|---|
| `ml/text.py: fold()` | свёртка казахских букв и частых опечаток (ә→а, қ→к, ң→н, і→и, щ→ш…): «жатакхана» = «жатақхана», «обшежития» = «общежития» |
| `ml/lexicon.py` | словарь 24 тем университета: разговорные слова и синонимы RU/KZ/EN → официальные термины (query expansion), тематический буст при поиске, синонимы считаются подтверждением в guard'е |
| `ml/followup.py` | диалог: «қазақша нұсқада бер», «на русском», «подробнее», «а для магистрантов?» — используют предыдущий вопрос; приветствие / благодарность / «неге қате жауап бердің» |
| `ml/qtype.py` | **классификатор типа вопроса** (наша softmax-регрессия): как сделать / какие документы / сроки / сколько / куда обращаться / условия / что такое |
| `ml/composer.py` | **ранкер предложений** (наша логистическая регрессия, обучается self-supervised на псевдо-вопросах из документов) + сборка ответа: «Коротко» → шаги/список, очистка номеров пунктов, приоритет документа на языке вопроса |

### Портал и факты

* `frontend/index.html` — страница в стиле студенческого портала: плитки меню (ЭДО, Трансферт, Силлабус, Add & Drop,
  Заявления, Карьер центр, Мой эдвайзер, ИУП, Транскрипт, Расписание, Журнал, Экзамены, Стипендия, Общежитие …),
  каждая плитка задаёт вопрос AI-консультанту; версия для слабовидящих, 3 языка, панель консультанта справа.
  Прежний полноэкранный чат — `frontend/chat.html`.
* `ml/facts.py` + `scripts/07b_extract_facts.py` — извлечение фактов «должность → ФИО» из блоков подписей документов
  («Председатель Правления – Ректор ____ М. Бегентаев»), голосование по всем вхождениям; отвечает на «Ректор кім?».
* Справочник первокурсника (Freshman guide, 57 стр.) входит в корпус (`data/raw/extra/`).

**В проекте нет ни одной готовой (pre-trained) модели и внешнего API** — все модели (язык, scope, тип вопроса,
embedding, reranker, ранкер предложений) реализованы и обучены нами на документах университета (`scripts/04–08`).
Каждое предложение ответа взято из официального документа, поэтому ответ не может содержать выдуманных фактов.

## Эксперименты (scripts/09_evaluate.py)

Тестовый набор: **10 категорий × 10 вопросов × 3 языка = 300 вопросов** (admission, education, exams, scholarship,
dormitory, academic leave, transfer, internship, graduation, student services) + 30 вопросов не по теме + 15 вопросов,
ответа на которые нет в документах. Для каждого вопроса указан ожидаемый официальный источник.

1. **Embedding A vs B** — LSA без обучения vs LSA + контрастивное дообучение.
2. **Dense vs BM25 vs Hybrid vs Hybrid + reranker.**
3. **Top-3 / Top-5 / Top-10.**
4. **Русский vs Қазақша vs English** — accuracy, Recall@5, MRR, faithfulness, hallucination rate, citation accuracy, латентность (avg / P50 / P95).

Результаты: `reports/evaluation_report.md`, `reports/evaluation_results.json`, графики `reports/figures/*.png`,
`reports/per_question.csv` (с пустой колонкой `human_score_0_2` для ручной оценки).

## Результаты (обучение на ноутбуке, 26.09.2026)

Корпус: **491 официальный документ** (RU/KZ/EN, в т.ч. сканы, распознанные OCR, и «Анықтама-кітапша первокурсника»),
6 322 страницы, **12 095 фрагментов**.

| Модель | Результат |
|---|---|
| Language detector (char n-gram NB) | 97.5 % на предложениях, 100 % на 300 вопросах |
| Scope classifier | F1 = 0.978 (289/300 вопросов по теме приняты, 28/30 посторонних отклонены) |
| Embedding model | Recall@5 на валидационных парах: 0.568 (LSA) → 0.656 (после InfoNCE) |
| Reranker | MRR: 0.599 → 0.675, Hit@1: 0.443 → 0.504 |

Полный RAG-pipeline на 300 тестовых вопросах (hybrid + reranker, Top-5):

| Метрика | Русский | Қазақша | English | Все |
|---|---|---|---|---|
| Ответ с правильным источником | 0.640 | 0.700 | 0.700 | 0.680 |
| Recall@5 | 0.870 | 0.880 | 0.790 | 0.847 |
| MRR | 0.710 | 0.726 | 0.694 | 0.710 |
| Доля отвеченных вопросов | 0.900 | 0.940 | 0.980 | 0.940 |
| Faithfulness | 1.000 | 1.000 | 1.000 | 1.000 |
| Hallucination rate | 0.133 | 0.133 | 0.133 | 0.133 |
| Средняя задержка, мс | 234 | 241 | 243 | 239 |

Отказы: вопросы не по теме — 96.7 %, вопросы без ответа в документах — 66.7 %.
Сильные темы: академический отпуск (0.93), общежитие (0.90), приём (0.77); слабые: практика (0.17) и стипендии (0.50).
Наблюдение для диплома: контрастивное дообучение улучшает поиск на автоматически созданных парах,
но на реальных вопросах студентов даёт почти тот же результат, что и LSA (Recall@5 0.830 vs 0.817) —
обучающие пары (Inverse Cloze Task) отличаются от настоящих вопросов.

> Пороги «защиты от галлюцинаций» (`models/config.json`) подобраны по этому же тестовому набору,
> поэтому показатели отказов могут быть немного завышены; для строгой оценки нужен отдельный валидационный набор.
> Подробно: `reports/evaluation_report.md`, графики — `reports/figures/`.

В GitHub не попадают: обученные модели (`models/`), скачанные документы (`data/raw`, `data/processed`),
корпуса (`data/lm`, `data/translation`), `_training_files/`, логи и `.env`. Модели воспроизводятся скриптами
`2_train_all.bat`, `12–16_*.bat`. Схема: [`docs/architecture`](docs/architecture/README.md).

## Безопасность

JWT-аутентификация, роли student/admin, хэширование паролей PBKDF2-SHA256 (200 000 итераций), rate limiting,
валидация входных данных (Pydantic), защита от SQL-инъекций (SQLAlchemy ORM / параметризованные запросы), CORS,
секреты только в `.env` (не хранится в GitHub).

## Docker (PostgreSQL + pgvector)

```bash
docker compose up --build        # frontend :8080, backend :8000, postgres + pgvector
```
Модели сначала обучаются (`python scripts/run_all.py`), папка `models/` монтируется в контейнер; при первом запуске
документы и векторы фрагментов записываются в таблицы `documents` / `document_chunks` (pgvector, HNSW-индекс).

## Ручной запуск (без .bat)

```bash
python -m venv .venv && .venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python scripts/run_all.py                                 # или по шагам 01 … 09
python -m uvicorn backend.app.main:app                    # http://127.0.0.1:8000
python -m pytest -v
```
